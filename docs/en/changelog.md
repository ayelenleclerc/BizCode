## [Unreleased]

### Added

- **MFA / TOTP (#213):** optional or role-required two-factor auth (`super_admin`, `owner`, `manager`, `finance`, `auditor`); AES-GCM TOTP secrets (`BIZCODE_MFA_ENCRYPTION_KEY`); Redis MFA login challenges (`mfaRequired` + `mfaToken`, 5 min, single-use); `POST /api/auth/mfa/verify|setup/start|setup/confirm|disable` and admin `PATCH /api/users/{id}/mfa`; 8 single-use backup codes (scrypt); `/me` flags `mfaEnabled` / `mfaSetupRequired`; login MFA step + Settings → Security UI with QR; banner when setup required; OpenAPI + i18n EN/ES/PT-BR. Out of scope: WebAuthn/SMS, App Seller, RLS (#215), secrets manager (#216).

- **Refresh token rotation + Redis blacklist (#212):** opaque access cookie (`bizcode_session`, 15 min) and refresh cookie (`bizcode_refresh`, 7 days or 30 with `rememberMe`); `POST /api/auth/refresh` rotates the pair; reuse of a revoked refresh invalidates the token family; logout and password change blacklist refresh hashes (Redis when `REDIS_URL` is set, in-memory otherwise for unit tests); local Redis via `docker-compose.redis.yml`; api-client interceptor retries once after refresh on 401; i18n EN/ES/PT-BR. Out of scope: MFA (#213), RLS, WAF, Dependabot.

- **Units of measure / cut-to-size (#203):** module `inventory.uom` (pro, depends on `inventory.stock` + `core.catalog`); `Articulo` fields `unidadBase` (`unidad`/`kg`/`gramo`/`litro`/`metro`/`m2`/`m3`/`rollo`/`caja`), `unidadCompra`, `factorConversion`, `multiploVenta`, `pesoKg`, `volumenM3`; pure helpers `UNIDAD_BASE_VALUES`, `umedidaFromUnidadBase`, `allowsDecimalQuantity`, `toBaseQuantity`/`fromBaseQuantity`, `roundQty`, `validateQuantityForUom` in `@bizcode/types`; article form shows the UoM fields (behind the module and only for `tipo !== 'servicio'`) and auto-derives the legacy `umedida` code from `unidadBase`; new-invoice line quantity switches to decimal step/`inputMode` when the article's unit allows it and shows the unit next to the quantity; purchase-order receive dialog allows decimal quantities and hints the purchase-unit conversion factor when different from 1; i18n EN/ES/PT-BR. Out of scope in this UI/i18n pass: OpenAPI contract updates (separate track).

- **FEFO lots and expiry (#202):** modules `inventory.fefo` (pro) and `inventory.lots` (enterprise); Prisma `ConfigFefo` / `Lote` plus `Articulo.controlLote` and optional `loteId` on `FacturaItem` / `PedidoItem` / `StockAjuste` (Int IDs); purchase receive requires lot + expiry when control is on; invoice create allocates FEFO (expiry ASC) and may split lines per lot; stock adjustments require coherent `loteId`; transfers / physical counts / production orders return `422 LOT_CONTROL_UNSUPPORTED` for lot-controlled articles until a follow-up; daily job `npm run lotes:vencimiento` notifies managers (`lot_expiring`); API `/api/fefo/config`, `/api/lotes*`, `/api/articulos/{id}/trazabilidad`; UI `/lotes`, article toggle, OC receive fields; OpenAPI, tests, i18n EN/ES/PT-BR. Limitations: does not replace SENASA/ANMAT regulatory records; no GS1-128 scanner; FEFO not in seller app/portal; lot moves on transfers/counts/OP deferred.

- **Customer loyalty points (#250):** module `clients.loyalty`; Prisma `ConfigFidelizacion` / `PuntosFidelizacion` / `MovimientoPuntos` (Int IDs); accrual on active invoice issue (not on collection); optional `puntosCanje` on invoice create as a negative ad-hoc line; void reverses linked movements; expiry job `npm run fidelizacion:vencimiento` (FIFO lots + manager pre-notice / optional customer email); API `/api/fidelizacion/*` + portal `GET .../fidelizacion`; PDF/ticket footer legend; UI `/fidelizacion`, customer panel, invoice redeem control; OpenAPI, tests, i18n EN/ES/PT-BR. Limitations: points liability is an operational KPI (not a GL entry); redemption treated as net total reduction aligned with current invoice math; no seller-app display; no portal push; WhatsApp to portal customer out of scope.

- **Production orders (#249):** module `production.orders` (depends on `production.bom`); Prisma `OrdenProduccion` / `OrdenProduccionInsumo` / `StockReservaProduccion` (Int IDs); planning freezes the BOM projection of the active formula; availability = `StockDeposito.cantidad` minus active reservations of other orders, with detailed shortfall lines; flow `planificada → en_proceso` (soft reservation, no stock move) `→ completada` (real consumption, finished-goods credit, `costoTotal`) or `cancelada` (releases reservations); waste recorded as `StockAjuste` with motives `produccion_consumo` / `merma_produccion` / `produccion_alta`; missing inputs can generate a draft `OrdenCompra` via `CompraService`; API `/api/ordenes-produccion/*` (rate-limited mutations, `inventory.adjust` on start/complete); UI `/ordenes-produccion`; OpenAPI, tests, i18n EN/ES/PT-BR. Limitations: integer stock rounding (consumption up, production down), `tipo=servicio` lines cost but do not move stock, cost uses current `Articulo.costo`. Out of scope: expected waste percentage in the formula, FEFO/lots (#202), automatic purchase order dispatch, nested BOMs.

- **Production BOM formulas (#248):** module `production.bom`; Prisma `FormulaProduccion` / `FormulaInsumo` (Int IDs, versioned active formula per finished article); unit cost from `Articulo.costo` with margin vs `precioLista1`; purchase projection for N units; API `/api/formulas-produccion/*` (rate-limited mutations); UI `/formulas-produccion`; OpenAPI, tests, i18n EN/ES/PT-BR. Out of scope: production orders/stock moves (#249), nested BOMs, auto unit conversion.

- **Foreign-currency catalog prices and exchange rates (#243):** module `catalog.multicurrency`; Prisma `TipoCambio` plus FX fields on `Articulo`, `TenantConfig.tipoCambioPreferido`, and invoice/line TC snapshots; BCRA official USD sync (`npm run tipos-cambio:bcra`, schedule ~10:00 `America/Argentina/Buenos_Aires`); manual MEP/CCL/blue/manual rates; recalc of FX `precioLista1` (ARS) with manager notification `precios_fx_actualizados`; API `/api/tipos-cambio/*` (rate-limited mutations); invoice/PDF snapshot; UI `/tipos-cambio` + article currency fields; OpenAPI, tests, i18n EN/ES/PT-BR.
